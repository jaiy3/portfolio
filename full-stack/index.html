Selected work

PayLedger

A payments ledger with a dashboard you can try to break. Every visitor gets a private sandbox to move money, retry requests and fire transfers at the same moment.

  • Built the React and TypeScript dashboard and the API behind it. It shows each entry's debits and credits totalling zero, webhook retries as they happen, and a 20-at-once concurrency test drawn live.
  • Accounts are locked in a fixed order inside each transaction, so simultaneous transfers never overdraw a balance or deadlock. Idempotency keys make retries safe.
  • PostgreSQL enforces the ledger rules on its own, and webhooks use a transactional outbox with HMAC signatures and backoff.

React, TypeScript, Vite, Express, PostgreSQL, Vitest, Docker, GitHub Actions

AtlasAI

Ethereum portfolio analytics with an AI assistant that answers from the wallet's real data instead of guessing.

  • React and TypeScript dashboard covering balances, tokens, NFTs, a 7-day activity chart, a live price watchlist and an AI chat panel, with loading, empty and error states throughout.
  • Wallet connection with WalletConnect, RainbowKit, Wagmi and Viem, plus register and login flows backed by JWT auth.
  • The public demo loads a real wallet, so visitors see live data without an account. The API fans out to four Alchemy sources in parallel and returns one priced portfolio.
  • The assistant is given the actual holdings plus live prices for any asset the question mentions, and is told never to invent balances.

React, TypeScript, Vite, Wagmi, Viem, RainbowKit, Express, PostgreSQL, Prisma, Alchemy, OpenRouter

MarketPulse

A real-time crypto market data API with a live browser dashboard. It ingests Binance trades, fans them out over WebSockets and keeps a queryable price history.

  • Built the dashboard on the API's own WebSocket and REST endpoints: streaming prices, canvas sparklines, a throttled trade feed and stored history.
  • Redis pub/sub sits between ingestion and delivery, so any number of API instances can push the same trade to their clients.
  • Database writes go through a BullMQ queue with retries and idempotent job IDs, so bursts and replays never create duplicate rows.

TypeScript, Express, PostgreSQL, Prisma, Redis, BullMQ, WebSockets, Docker
